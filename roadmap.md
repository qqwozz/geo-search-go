🗺️ Roadmap: API поиска ближайшей недвижимости

### Этап 1: Подготовка данных

- [ ] Выбрать БД (PostgreSQL с PostGIS или обычный PostgreSQL с координатами)
- [ ] Создать таблицу `properties` с полями: id, адрес, цена, комнаты, площадь, lat, lon
- [ ] Добавить индексы на поля: lat, lon, price, rooms (для быстрых фильтров)
- [ ] Наполнить таблицу тестовыми данными (хотя бы 100-1000 объектов)

### Этап 2: Реализация гео-логики

- [ ] Написать функцию расчета расстояния между двумя точками (формула Гаверсинуса)
- [ ] Решить как будете фильтровать:
  - **Вариант А (простой):** Выбрать все объекты, вычислить расстояние для каждого, отсортировать
  - **Вариант Б (быстрый):** Сначала отсечь объекты по квадрату (lat/lon в диапазоне), потом вычислять расстояние
  - **Вариант В (профи):** Использовать PostGIS с индексами

### Этап 3: Создание API эндпоинтов

- [ ] Сделать POST `/api/properties/nearby` который принимает:
  - lat, lon (точка поиска)
  - radius (опционально, радиус в метрах)
  - min_price, max_price, min_rooms, max_rooms, min_area, max_area (фильтры)
  - limit (сколько результатов вернуть)
- [ ] Сделать GET `/api/properties/{id}` для получения деталей объекта

### Этап 4: Оптимизация производительности

- [ ] Добавить пагинацию (offset/limit) если объектов много
- [ ] Закешировать частые запросы (Redis или in-memory cache)
- [ ] Если объектов > 100к, перейти на PostGIS (индекс GIST даст мгновенный поиск)

### Этап 5: Тестирование и деплой

- [ ] Написать unit-тесты для функции расстояния
- [ ] Протестировать API с разными фильтрами
- [ ] Замерить время ответа (должно быть < 100ms)
- [ ] Задеплоить (Docker + любой хостинг)

## 📦 Что нужно изучить/использовать

**Библиотеки Go (минимальный набор):**

- `net/http` или `gin` (для API)
- Драйвер для PostgreSQL (`lib/pq` или `pgx`)
- `math` (для вычислений расстояния)

**Если хотите упростить себе жизнь:**

- Используйте PostGIS сразу — он делает всю геометрию за вас
- Возьмите готовую библиотеку `github.com/paulmach/orb` для гео-операций

## ⚡ Главные решения которые нужно принять

1. **Будете использовать PostGIS или нет?**

   - **Нет:** пишете формулу расстояния сами, поиск медленнее на больших данных
   - **Да:** все гео-операции в БД, очень быстро, но нужно изучить PostGIS
2. **Как фильтруете по расстоянию?**

   - Простой способ: считать расстояние для всех объектов (медленно при 100к+)
   - Умный способ: сначала отсечь по bbox, потом считать (быстрее)
   - Профи способ: использовать spatial index (PostGIS)
3. **Где хранить координаты?**

   - Два отдельных поля (lat, lon) — проще для понимания
   - Одно поле типа POINT — правильно для гео-задач

## 🎯 Итоговая минимальная реализация (3-4 часа работы)

1. Поднимаете PostgreSQL
2. Создаете таблицу с lat/lon
3. Пишете функцию Haversine
4. Делаете HTTP handler который:
   - Принимает фильтры
   - Делает SELECT с WHERE условиями
   - Вычисляет расстояние для каждой записи
   - Сортирует и возвращает топ-N
5. Тестируете через curl/postman

## 📈 Что дальше если объектов станет много (100k+)

- Переход на PostGIS (один вечер переписать запросы)
- Добавление Redis кеша
- Предварительная фильтрация по стране/городу
- Шардирование данных по регионам
- [ ] Это всё. Начинайте с малого — обычный SQL + Haversine, потом усложняйте если понадобится.
